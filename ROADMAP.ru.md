# План развития @yumyum-player/ui

Аудит от 22 ноября 2026 года. Проверены исходная версия `@yumyums/ui@1.0.0`, [ревизия библиотеки](https://github.com/Vokinlemxela/yumyum-ui/tree/fb11a38294eeb50b75562cd2166abb7e92619c67) и три потребителя — веб-клиент ВМС, сайт и отладчик Player.

**Предлагаемое направление.** Оставить один npm-пакет и один цикл выпуска. Дать приложениям отдельный импорт базовых компонентов и отдельный импорт видеоинтерфейса. Сохранить корневой импорт для существующих клиентов. Приложения, которым нужны оба слоя, смогут по-прежнему фиксировать одну версию. Первую пользу даст исправление уже воспроизводимых ошибок в форме настроек и при смене видеоисточника.

## Что можно использовать сегодня

| Компоненты | Применение и границы |
| --- | --- |
| `Button`, `Input`, `Select`, `TextArea` | Обёртки над нативными элементами React DOM. Уже используются в форме заявки, входе в систему и администрировании пользователей. У `Input` есть `error` для оформления и `aria-invalid`. Подпись поля, текст ошибки и связь между ними задаёт приложение. |
| `Checkbox`, `Toggle` | Подходят для фильтров и настроек. Первый использует нативный checkbox, второй — кнопку с `role="switch"` и управляемым `checked`. Примеры — фильтр событий и настройки детектора движения. |
| `Badge`, `Spinner` | Подходят для статусов и ожидания загрузки. Сайт уже использует оба. У `Badge` есть специализированный вариант `rec`. У `Spinner` зафиксированы размер 40 px и доступное имя `Loading...`. |
| `Slider` | Обычный числовой диапазон с `min`, `max` и `step`. В ВМС меняет параметры детектора, в плеере — громкость. Поддерживает стрелки и Home/End. Его публичные props и итоговая разметка пока не позволяют связать ползунок с доступным именем. |

Все девять компонентов работают без видеодвижка. В манифесте внешними зависимостями для потребителя указаны React и React DOM. Общие стили используют переменные `--yyp-*` с тёмными значениями по умолчанию. Компоненты вставляют CSS через `useEffect` в `document.head`; при серверном рендеринге этот CSS появляется только после запуска клиента. [Примитивы и стили](./src/primitives.tsx) · [Манифест](./package.json)

## Где проходит граница с Player

- **Импорты.** Корневой модуль экспортирует и примитивы, и `YumYumPlayerView`. Видеооболочка импортирует `Badge`, `Button`, `Slider` и `Spinner` обратно из корня. Это цикл модулей. Объём кода плеера в готовом бандле зависит от сборщика и его удаления неиспользуемого кода.
- **Контракт движка.** Хост передаёт стабильную фабрику `createPlayer(canvas)`. Оболочка владеет canvas, опрашивает `getTelemetry()` каждые 250 мс, распознаёт состояние `PLAYING`, использует счётчик отрисованных кадров и события воспроизведения. Для другого движка нужен адаптер. Выбор потока, транспорта и камеры уже выполняет приложение.
- **Поведение интерфейса.** Меню качества получает список уровней, но предлагает фиксированные `auto`, `main`, `sub`. Источник с уровнями `360p` и `720p` не получает в меню свои варианты. Таймлайн, PiP через копирование canvas в video, горячие клавиши и восстановление громкости из localStorage относятся к видеосценариям. Режим `chrome="none"` скрывает контролы, но оставляет жизненный цикл и опрос. В jsdom с имитацией API захвата после первого кадра даже при скрытой панели и отключённой кнопке PiP оболочка вызвала `canvas.captureStream(30)`. Стоимость для реальной видеостены нужно измерить в браузере.
- **Обнаруженный дефект.** В проверке React DOM/jsdom первая фабрика завершилась ошибкой, вторая вернула исправный handle в тот же экземпляр компонента. После `onReady` нового источника надпись `Playback error` осталась. Флаг `hasError` также блокирует переключение play/pause. [Контракт, жизненный цикл и меню качества](./src/YumYumPlayerView.tsx)
